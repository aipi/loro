# ADR-0004 — Acervo efficient-reading layer (summary card, stable IDs, protocol)

- **Status:** accepted (owner decision, 2026-07-29)
- **Context:** the acervo is read far more often than it is written — by the
  loop, by `/loro-ask`, by the meeting AI and by any external agent pointed at
  it. Plain markdown reads fine, but *whole-file* reading wastes tokens and
  blurs precision as contexts grow. Retrieval infrastructure (vector RAG,
  knowledge graphs) was considered and rejected for now: it adds dependencies
  and an index that can drift from the source of truth, while the observed
  problem is editorial (granularity), not lexical. The decision is a reading
  layer made of structure only, generated and maintained by the loop itself.

## Decision

### §1 Summary card (`## 0 · Sumário` / `## 0 · Summary`)

Every `context.md` opens with a section 0: a quick-read card of 1 line per
section plus the key IDs, regenerated by the loop on every update (it is
derived content — always safe to rewrite). Agents read the card first and open
only the section they need; the full file is the fallback, not the entry point.
The business sections keep their numbering (1–6); the card is additive, so
existing acervos degrade gracefully (a missing §0 simply means whole-file
reading until the loop next touches the context).

### §2 Stable, greppable IDs

- **Decisions (section 5):** `D-YYYY-MM-DD-<slug>`.
- **Hotspots (section 6):** `H-<n>`, numbering local to the file, never reused.

IDs make any item addressable by search (`grep H-3`) — deterministic retrieval
with near-zero token cost. They are cited in the CHANGELOG and in `INDEX.md`.

### §3 Enriched `INDEX.md` line

One line per context, regenerated by the loop:
`- **<context>** — <1-sentence description> · updated YYYY-MM-DD · hotspots H-1..H-<n>`.
The goal is routing *without opening files*: description picks the context,
the date signals staleness, the hotspot range exposes the open-question load.

### §4 Reading protocol (taught, not assumed)

The generated `AGENTS.md` carries an explicit protocol — `INDEX.md` first →
summary card (§0) → ID search → targeted section read — and every generated
skill (`/loro-context`, `/loro-ask`, `/loro-analyse`, `/loro-question`,
`/loro-note`) repeats it as a rigor rule ("cheap reading"), in both languages.
Structure without protocol does not change agent behavior.

### §5 Out of scope (deferred)

BM25/embedding indexes (e.g. tantivy, sqlite-vec) stay out until an acervo
demonstrably outgrows grep + index routing (tens of contexts). Any such index
must live inside the acervo, be derived (rebuildable from markdown) and respect
the acervo boundary — no cross-acervo indexing (BR-1 posture). Machine-oriented
duplicate formats (JSON/YAML mirrors of `context.md`) are rejected: markdown is
the single source, readable by both audiences.

## Consequences

- `templates.rs` molds and skills changed; tests assert the card, the ID
  conventions and the protocol in both languages.
- The repo's own brain (`brain/`) adopts the same layer (dogfooding).
- Existing acervos are untouched until the loop next rewrites a context — the
  loop's "respect existing structure, fill gaps" rule covers the migration.
